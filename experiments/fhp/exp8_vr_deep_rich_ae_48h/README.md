# Experiment 8: VR-DeepPDCFR+ with UCV's rich AE representation

## Scientific question

Does adding the **same strategic inputs** used by the selected UCV system close
its Experiment 40 advantage? This experiment trains only VR-DeepPDCFR+; it does not
retrain or modify UCV. The companion experiment lives in the other FHP learner's
repository, also numbered 8.

UCV reference: `exp38-rich48-20261019-230016`, 48-hour policies, seeds 0/1/2,
continued from `exp36-rich2500-20261018-205125`. Encoder source is pinned to
UCV commit `6ab85bbcd03627281e411243419d64ce9e9236d5`; its relevant feature files
were verified unchanged in the current checkout. This is a selected historical
reference, not a fresh independent replication of UCV.

## Frozen contract

- Start from this repository's selected Experiment 6 learning configuration.
- Train **from scratch**, seeds **0, 1, 2**, one `n2-standard-16` VM per seed.
- Eight traversal actors. Preserve native learner threads, sampling, replay
  capacities, minibatches, optimiser, fitting steps and network hidden layers.
- Change only the feature representation and the input/replay dimensions it
  requires. Extra first-layer parameters and feature-computation costs are
  consequences of the new inputs; this is not a fixed-parameter-count study.
- **48 active training hours**, exports at 6/12/18/24/30/36/42/48 hours; stop at
  the first completed outer iteration crossing the final threshold. Record
  overshoot and actual counters. The cloud worker has a 72-hour safety cap,
  which is not a 72-hour training allocation.
- Final complete training state retained; intermediate exports are playable
  policies. Production launchers accept fresh runs only, with no warm start.
- No automatic tuning, early selection of the best checkpoint, or baseline
  changes in response to match outcomes. The primary endpoint is 48 hours.

The pinned encoder yields **231 player features** and **359 critic features**.
Player inputs use own cards and public history only. Uniform-range strength
enumerates 1,081 compatible holdings, not the opponent's actual cards or range.
Native critics may access both hands as before; policies never do. Source hashes,
full encoder metadata and the UCV reference run are recorded with each worker.
Both repos vendor identical encoder code, so no sibling checkout or moving
external dependency is required. AE does not use the separate preflop-D asset.

## VR-specific preservation

Keep the native 3x64 MLPs, predictive/discounted regret updates, critic fitting
budget, sampler and average-policy fitting schedule. In particular, do not copy
UCV's 2,500 critic-update count or its network architecture into VR.

Both the central learner and all eight traversal replicas receive the AE encoder.
The critic retains its full-state inputs, with next-player information stored
separately as a 231-value vector; never slice player information from a
privileged/global critic representation. Saved average-policy snapshots reload
through the versioned encoder factory. Legacy snapshots keep their original
encoder and dimensions.

Use Experiment 6's cumulative active solver clock, excluding Ray startup,
checkpoint policy fitting, persistence, validation and uploads. Feature
construction during learning is included. Record worker wall time and fitting
phase timings separately. This follows the established nominal training-time
comparison with UCV; it is not an equal-total-cost claim.

## Validation and launch

Run functional tests (the production environment installs pinned requirements):

```bash
python3 -m pytest -q tests/test_exp8_rich_ae.py
bash gcp/run_exp8_vr_deep_rich_ae_48h.sh smoke-local
```

`smoke-local` runs actual Ray actors and writes only to a fresh temporary output
directory. Ordinary tests use the same actor implementations with local execution;
the separately gated real-Ray tests verify process transport. Reference fixtures
contain player and critic vectors generated by the pinned UCV implementation for
28 states. Tests check exact equality, hidden-card privacy, suit invariance,
configuration preservation, saved-policy loading, full-state integrity and cloud
job generation. SD additionally tests lossless continuous replay.

Set `PROJECT_ID`, `REGION`, `BUCKET`, `SA_EMAIL`, and a **pushed full commit SHA**
in `REPO_REF`. Choose a fresh `RUN_ID` (or let the launcher generate one):

```bash
bash gcp/run_exp8_vr_deep_rich_ae_48h.sh dry-run
bash gcp/run_exp8_vr_deep_rich_ae_48h.sh run
```

The default launcher action is `dry-run`. It does not submit jobs. `run` submits
a controller that first gates on tests and short Ray training, then launches
three independent training VMs and aggregates their completed artifacts.
No full match league or LBR stage is automatically launched. An unsuccessful
smoke prevents paid production training. Ray tests run in cloud smoke before the three long runs; local tests do not certify Linux timing.

The new experiment must be committed and pushed before cloud submission. A
launcher guard rejects a revision without the required Experiment 8 files.
Neither implementation nor dry-run starts the 48-hour jobs.

## Comparison after both experiments finish

Use all nine cross-seed pairings for each pair of algorithms, not just identically
numbered seeds. Reuse UCV Experiment 38's frozen 48-hour policies. Use fresh
seat-swapped duplicate deals and the native loaders from the **new pinned SD/VR
commits**, since older evaluation checkouts do not recognise rich AE artifacts.
Preserve SD's full strategy archive and per-hand mixture semantics. The training
artifacts include all six-hour checkpoints; only 48 hours is the primary endpoint.

The planned league follows Experiment 40's 100,000 duplicate pairs per seed cell
and reports uncertainty across trained policies, separately from match-deal
noise. This README specifies the downstream evaluation; the new launchers train
and aggregate their own learner only. The three-way evaluation job is separate.

Interpretation: if UCV retains a consistent advantage, exclusive access to rich
AE features cannot explain the previous gap. Architecture, optimisation and
historical selection differences remain; do not claim this experiment isolates
a single UCV mechanism, establishes exact FHP exploitability, or gives fresh
independent confirmation of UCV training reliability.
